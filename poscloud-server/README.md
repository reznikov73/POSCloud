# POSCloud Server — серверное приложение (Wails)

Отдельное приложение-сервер: хранит файлы и отдаёт их клиентам по сети. Запускается **на серверном ПК**,
слушает выбранный порт. Клиент на другом ПК подключается к нему по адресу и порту.

## Запуск

```powershell
cd poscloud-server
.\build\bin\poscloud-server.exe
```

Пересборка после правок: `wails build -s -skipbindings -webview2 browser`

## Что в UI

- **Порт** и **каталог хранения файлов** (с выбором папки);
- индикатор: работает / остановлен / **порт занят другим процессом**;
- кнопка **Запустить/Остановить** — одна кнопка, меняющая назначение;
- кнопка **Освободить порт** — останавливает наш сервер, а если порт занят **сторонним процессом**,
  показывает его имя и PID и после подтверждения завершает именно этот процесс;
- **«Адрес для клиентов»** — готовый `http://<ваш-IP>:<порт>` (берётся локальный IPv4), его вводят в клиенте;
- список файлов на сервере (с удалением) и журнал.

## Флаги запуска

| Флаг | Назначение |
|---|---|
| `-port 8090` | порт прослушивания |
| `-data D:\share` | каталог хранения |
| `-autostart` | запускать сервер сразу при открытии программы (включено по умолчанию; `-autostart=false` — не запускать) |

Если флаг не указан, берётся значение из сохранённых настроек (`server.json`).

## Уборка пустых каталогов

Протокол синхронизации удаляет файлы, но не каталоги. Поэтому сервер после каждого удаления подчищает
опустевшие папки (снизу вверх, до первого непустого), а при запуске разово проходит по всем
пользователям и убирает скелет, накопившийся раньше. Служебные каталоги (`.blocks`, `.manifest.json`)
не затрагиваются: обход пропускает имена, начинающиеся с точки, а непустой каталог удалить невозможно.

## Автозапуск

В программе два разных «автозапуска», и в интерфейсе для них теперь две отдельные галочки:

| Галочка | Что делает | Где хранится |
|---|---|---|
| **Запускать сервер при открытии программы** | Сразу после старта поднимает сервер (включено по умолчанию) | `server.json`, поле `autoRun` |
| **Запускать программу при входе в Windows** | Добавляет программу в автозагрузку Windows | реестр `HKCU\...\Run` |

Кнопки «Запустить/Остановить» и «Освободить порт» работают всегда. Ключ `-autostart=false` отменяет
запуск на один раз, но действует **только когда указан явно**; иначе берётся значение галочки.

## Освободить порт

Кнопка ведёт себя по-разному:

1. Если сервер запущен этим приложением — он просто останавливается.
2. Если порт свободен — так и сообщается, ничего не происходит.
3. Если порт занят **сторонним процессом** — приложение показывает его имя, PID и путь к файлу и
   просит подтверждение. Только после подтверждения этот процесс завершается.

Завершение выполняется строго по PID, который в момент нажатия действительно слушает указанный порт:
приложение никогда не завершает само себя и не трогает процесс, если владелец порта успел смениться.

## Повторный запуск

Программа работает только в одном экземпляре. Если она уже запущена (в том числе когда окно закрыто
и свёрнуто в трей) и её запускают снова, второй экземпляр не стартует: окно уже работающей программы
показывается и выводится на передний план, а повторный запуск сразу завершается.

## Код подключения клиента

На странице «Сервер» нажмите **«Код подключения»**, выберите пользователя и скопируйте код. В нём есть адрес, порт, TLS-отпечаток и одноразовый секрет; код действует 10 минут и после успешного подключения погашается. Постоянный токен в код не попадает и в журнал не записывается.

Клиент вставляет код в поле **«Код с сервера»** и нажимает **«Подключить»**. Если код утерян или истёк — создайте новый.

API: `POST /pair` принимает `{"code":"pcp_...","deviceName":"..."}` и возвращает обычный токен устройства. Endpoint не требует Bearer-токена, но защищён одноразовым кодом и ограничением попыток с одного IP.

## Резервные копии и восстановление

В разделе **«Обслуживание»** можно сохранить ZIP с `server.json`, `users.json`, токенами и TLS-сертификатом/ключом. Файлы пользователей и история версий в копию не входят — для них работает отдельная история/корзина.

Восстановление доступно только при остановленном сервере. Перед заменой текущие служебные файлы сохраняются в каталог `.restore-backup-*`. После восстановления сервер нужно запустить снова.

Не сохраняйте резервную копию в папке синхронизации: в ней лежат токены и TLS-ключ, и она может уехать на сервер как обычный файл.
## API (для клиента)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | проверка доступности |
| GET | `/list` | список файлов (JSON) |
| POST | `/upload?name=` | загрузка файла |
| GET | `/download?name=` | скачивание файла |
| DELETE | `/delete?name=` | удаление |

## Сеть

Для доступа из интернета нужен публичный адрес: проброс порта на роутере, либо размещение на VPS
с доменом. Транспорт — HTTP по умолчанию; в настройках сервера можно включить HTTPS: сервер создаёт
самоподписанный сертификат, клиент проверяет его SHA-256-отпечаток. После смены режима сервер нужно
перезапустить, а в клиенте указать HTTPS и отпечаток.
