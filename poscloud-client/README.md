# POSCloud Client — клиентское приложение (Wails)

Отдельное приложение-клиент: следит за вашей папкой и синхронизирует её с сервером по сети.
Запускается **на клиентском ПК** и подключается к серверу по заданному адресу и порту.

## Запуск

```powershell
cd poscloud-client
.\build\bin\poscloud-client.exe
```

Пересборка после правок: `wails build -s -skipbindings -webview2 browser`

## Что в UI

- поля **Адрес сервера** и **Порт** (то, что показывает серверное приложение);
- **Папка синхронизации** (с выбором папки) и **интервал опроса**;
- кнопка **Проверить связь** — сразу скажет, отвечает ли сервер по этому адресу;
- статус: работает / нет связи; время последнего синка;
- кнопка **Запустить/Остановить** — одна кнопка, меняющая назначение, и **Синхронизировать сейчас**;
- закладки: **Клиент** (настройки), **Исключения**, **Папки** (режимы подпапок), **Снимки**, **Файлы**, **Журнал**;
- блок **Исключения** — готовые наборы галочками, выбор из папки, импорт/экспорт и предпросмотр;
- список локальных файлов (с удалением) и журнал.

## Флаги запуска

| Флаг | Назначение |
|---|---|
| `-server 192.168.1.50` | адрес сервера (IP или домен) |
| `-port 8090` | порт сервера |
| `-dir C:\Sync` | папка синхронизации |
| `-interval 3` | интервал опроса, сек |
| `-autostart` | запускать синхронизацию сразу при открытии программы (включено по умолчанию; `-autostart=false` — не запускать) |

Если флаг не указан, берётся значение из сохранённых настроек (`client.json`), а при первом запуске —
значение по умолчанию (`localhost`, порт `8090`, интервал `3`). Явно указанный флаг всегда побеждает
сохранённую настройку, поэтому указанный в UI адрес сервера не сбрасывается при перезапуске.

## Автозапуск

В программе два разных «автозапуска», и в интерфейсе для них теперь две отдельные галочки:

| Галочка | Что делает | Где хранится |
|---|---|---|
| **Начинать синхронизацию при открытии программы** | Сразу после старта начинает работать (включено по умолчанию) | `client.json`, поле `autoRun` |
| **Запускать программу при входе в Windows** | Добавляет программу в автозагрузку Windows | реестр `HKCU\...\Run` |

При открытии без автостарта синхронизация не стартует; без токена доступа она тоже не запускается:
вместо цикла ошибок 401 причина пишется в журнал, а окно остаётся открытым для правки настроек.
Кнопки «Запустить», «Остановить» и «Синхронизировать сейчас» работают всегда.

Ключ `-autostart=false` по-прежнему отменяет запуск на один раз, но теперь он действует **только когда
указан явно**; если его не передавать, берётся значение галочки из настроек.

## Повторный запуск

Программа работает только в одном экземпляре. Если она уже запущена (в том числе когда окно закрыто
и свёрнуто в трей) и её запускают снова, второй экземпляр не стартует: окно уже работающей программы
показывается и выводится на передний план, а повторный запуск сразу завершается.

## Исключения (.poscloudignore)

Поле «Шаблоны» — это файл `.poscloudignore` в корне папки синхронизации: по одному шаблону в строке,
`#` — комментарий. Шаблон без `/` совпадает с любым сегментом пути (`node_modules`, `*.log` — на любой
глубине), шаблон с `/` — с полным относительным путём; поддерживаются `*`, `?`, `[...]`, `**`.
Игнорируемое не синхронизируется и не удаляется на сервере.

Заполнять список можно не только вручную:

- **готовые наборы** — галочки «Мусор Windows», «Временные файлы Office», «Проекты и сборки»,
  «Служебные каталоги VCS», «Логи», «Архивы», «Тяжёлые медиа». Набор записывается в файл отдельным
  блоком, поэтому его можно снять целиком, не задев строки, добавленные вручную;
- **Выбрать из папки…** — список реального содержимого папки синхронизации с галочками; можно зайти
  внутрь каталога. Каталог добавляется шаблоном вида `Папка/**`, то есть исключается вместе с содержимым;
- **Импорт… / Экспорт…** — загрузить список из файла или сохранить текущий;
- **Очистить** — очистить поле (файл изменится после «Сохранить исключения»);
- **Проверить** — предпросмотр: сколько файлов попадёт под исключения и сколько останется.

## Режимы папок (выборочная синхронизация)

Закладка **«Синхронизация»** показывает папки **с сервера** — даже те, которых на этом компьютере
ещё нет. Новые папки по умолчанию не скачиваются: они «ждут решения» — выберите режим или
нажмите «Скачать» (галочка сверху включает автоматическое скачивание). Правила хранятся
в `client.json` и действуют только на этом компьютере — на другом устройстве у той же папки
может быть свой режим.

| Режим | Локальные изменения | Изменения с сервера | Удаление локально | Удаление на сервере |
|---|---|---|---|---|
| **В обе стороны** (по умолчанию) | уходят на сервер | применяются | уходит на сервер | удаляет локально |
| **Только отправлять** | уходят на сервер | не применяются | уходит на сервер | не применяется |
| **Только получать** | не выгружаются | применяются | не применяется (файл вернётся) | удаляет локально |
| **Не синхронизировать** | — | — | — | — |

Как это работает:

- новые папки с сервера ждут решения, пока для них не выбран режим; уже синхронизированные папки
  продолжают работать без вопросов (внутри них ничего не спрашивается);
- пустые папки тоже переносятся: структура каталогов ездит вместе с файлами (скрытые и
  исключённые не трогаются);
- статус справа от имени показывает, есть ли копия на этом компьютере, а режим выбирается
  списком;
- правило выбирается по самому глубокому совпадению: можно отключить «Видео» целиком и оставить
  «Видео/Отпуск» отправляемым;
- «только отправлять» удобно для папок-источников (например, сканы на рабочем ПК): при расхождении
  выгружается версия этого устройства, конфликтные копии не создаются;
- «только получать» — зеркало сервера: локальные правки не выгружаются (при расхождении останется
  копия с пометкой «конфликт», а на месте файла будет серверная версия); случайно удалённый файл
  скачается заново;
- «не синхронизировать»: папка не сканируется и не отслеживается, файлы на сервере не трогаются;
- `.poscloudignore` продолжает работать поверх правил, но умеет только исключать файлы;
- «Убрать правило» снимает собственное правило папки — снова действует правило родительской
  папки, а если её нет — общий двусторонний режим; уже синхронизированные файлы остаются
  на месте;
- при отключении папки клиент предложит удалить её локальную копию (освободить место) — данные
  на сервере остаются; кнопкой «Убрать копию» это можно сделать и позже;
- «Удалить с сервера» убирает папку целиком: файлы удаляются на сервере (поэтому она исчезает
  и у других устройств), локальная копия, состояние и правила очищаются — список можно чистить.

## Снимки экрана

Три режима — «Снимок всего экрана», «Снимок активного окна» и «Снимок области»; кнопки есть и в окне
программы, и в меню трея, и на горячих клавишах:

| Клавиши | Что делают |
|---|---|
| `Ctrl+Shift+1` | снимок области: выделите прямоугольник мышью в окне |
| `Ctrl+Shift+2` | снимок окна, которое сейчас в фокусе |
| `Ctrl+Shift+3` | снимок всего экрана (все мониторы) |

### Редактор снимка

- Кнопка **«Редактировать…»** доступна после выделения области.
- Галочка **«Открывать редактор после снимка»** (по умолчанию снята) открывает редактор и после
  снимка всего экрана или активного окна.
- Инструменты: **стрелка**, **размытие** (пикселизация выделенного прямоугольника) и **текст**;
  рядом выбираются цвет и толщина.
- Ошибочную правку снимает кнопка **«Отменить шаг»** или **Ctrl+Z** (до шести шагов назад),
  а кнопка **«Вернуть исходный»** убирает все правки сразу — её тоже можно отменить.
- Правки наносятся на снимок в полном размере, поэтому качество не теряется.

Если сочетания заняты другими программами, их можно поменять на закладке **Снимки** в блоке
«Горячие клавиши»: нажмите нужную комбинацию прямо в поле. Нужен хотя бы один модификатор
(Ctrl, Alt или Shift), поддерживаются буквы, цифры и F1–F24, клавиша Delete очищает поле.
Пока вы вводите, старые сочетания временно отключены, а состояние каждого показано рядом
(«назначено» или причина, почему не вышло). Кнопка «Вернуть стандартные» возвращает
`Ctrl+Shift+1/2/3`. Сочетания хранятся в `client.json`.

- Снимок сохраняется в подпапку «Снимки экрана» внутри папки синхронизации и **уезжает на сервер**
  обычной синхронизацией; изображение заодно кладётся в буфер обмена, о чём сообщает уведомление.
- Галочка «Отправлять снимки на сервер» управляет этим: если снять — снимки сохраняются только
  на этом компьютере (в «Изображения\POSCloud»).
- Снимок области показывается прямо в окне приложения: координаты передаются долями от размера
  снимка, поэтому масштаб окна и DPI ни на что не влияют. Выбор можно начать из трея или горячей
  клавишей — окно выйдет вперёд само.
- Снимок окна делается через `PrintWindow`, поэтому получается даже если окно перекрыто другими;
  для свёрнутого окна будет сообщение об ошибке.
- Учтите: снимок экрана может содержать пароли и личные данные, а при включённой отправке он
  попадёт на сервер и станет доступен на других устройствах.

## Как связать с сервером

1. На серверном ПК запустите `poscloud-server.exe`, нажмите «Запустить» — увидите «Адрес для клиентов».
2. На клиентском ПК введите этот адрес и порт, выберите папку → «Проверить связь» → «Запустить».

Если ПК в разных сетях — между ними должен быть доступный маршрут (проброс порта/VPN/публичный IP).
