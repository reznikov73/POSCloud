# POSCloud

Синхронизация папок между своими устройствами: два небольших приложения для Windows — клиент и сервер.

- **poscloud-server** — хранит файлы пользователей и отдаёт их по HTTP.
- **poscloud-client** — следит за выбранной папкой и синхронизирует её с сервером.

Оба приложения написаны на Wails (Go + WebView2), живут в трее и не мешают работать:
закрытие окна не завершает программу.

## Возможности

**Клиент**

- синхронизация папки с сервером: опрос по интервалу, слежение за файлами (fsnotify) и подписка на
  изменения сервера (SSE) — файлы уходят и приходят без ожидания следующего цикла;
- **блочная передача**: файлы режутся на блоки по содержимому (SHA-256), передаются только те блоки,
  которых у другой стороны нет; повторяющиеся данные не пересылаются;
- **версии и удаления**: сервер ведёт манифест с версиями и «надгробиями» (tombstones), поэтому
  удаление и переименование доезжают до других устройств, а не приводят к возврату файла;
- **исключения** (`.poscloudignore`): готовые наборы галочками, выбор из папки, импорт и экспорт,
  предпросмотр («попадёт N из M файлов»);
- **снимки экрана**: весь экран, активное окно и произвольная область; настраиваемые горячие клавиши;
  редактор со стрелкой, размытием и текстом; снимок сразу попадает в буфер обмена;
- **автозапуск в двух смыслах**: начинать синхронизацию при открытии программы и запускать программу
  при входе в Windows — это две отдельные галочки;
- защита от двойного запуска: повторный запуск показывает окно уже работающей программы;
- контекстное меню в трее: состояние, пауза, «открыть папку», «синхронизировать сейчас», журнал.

**Сервер**

- HTTP API с **токенами устройств**: в реестре хранятся только хэши, открытый токен показывается один раз;
- **изоляция по пользователям**: у каждого своя папка, свой манифест и своё блочное хранилище;
- управление пользователями и токенами прямо в окне (создать, отключить, отозвать);
- **освобождение порта**: если порт занят чужой программой, сервер показывает её имя и PID и завершает
  только после подтверждения; собственный процесс не завершается никогда;
- автозапуск сервера при открытии программы, защита от двойного запуска, работа в трее;
- журнал запросов и список файлов в окне.

## Как это работает

Сервер для каждого пользователя ведёт **манифест**: имя файла → версия, размер, время, хэш и список
блоков. Обмен идёт по версиям, а не по всему каталогу:

1. клиент спрашивает `/changes?since=N` и получает только то, что изменилось;
2. для новых версий он узнаёт список блоков (`/blocks`) и выгружает или догружает недостающие
   (`PUT /block`, `/block`);
3. когда все блоки на месте, клиент фиксирует версию через `/commit` — только после этого файл
   становится виден остальным.

Блоки хранятся в `.blocks` и общие для всех версий файла, поэтому правка большого файла передаёт
только изменённую часть, а одинаковые файлы не занимают место дважды.

## Начало работы

1. **На серверном ПК** запустите `poscloud-server\build\bin\poscloud-server.exe`, нажмите «Запустить» —
   в окне появится «Адрес для клиентов» вида `http://192.168.х.х:8090`.
2. Создайте пользователя и устройство, скопируйте выданный **токен** (он показывается один раз).
3. **На клиентском ПК** запустите `poscloud-client\build\bin\poscloud-client.exe`, введите адрес, порт
   и токен, выберите папку синхронизации → «Проверить связь» → «Запустить».

Если компьютеры в разных сетях, между ними нужен доступный маршрут: проброс порта, VPN или публичный
адрес. Транспорт сейчас обычный HTTP — TLS отдельным шагом.

## Сборка

Нужны Go 1.25+ и Wails CLI v2.

```powershell
cd poscloud-client
wails build -s -skipbindings -webview2 browser

cd ..\poscloud-server
wails build -s -skipbindings -webview2 browser
```

Готовые файлы появляются в `build\bin\`. Иконку и оконные ресурсы подкладывает только `wails build`:
собранный вручную через `go build` exe останется **без иконки**.

## Проверка

```powershell
cd poscloud-client; go test ./...
cd ..\poscloud-server; go test ./...
```

Тесты покрывают: сохранение и приоритет настроек, защиту от двойного запуска, иконку трея,
работу со списком исключений, разбор и регистрацию горячих клавиш, снимок экрана и сохранение файла,
освобождение порта (включая завершение стороннего процесса-слушателя).

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | проверка доступности (единственный путь без токена) |
| GET | `/whoami` | какой пользователь и устройство обратились |
| GET | `/list` | список файлов пользователя |
| GET | `/manifest`, `/changes?since=` | манифест и изменения с указанной версии |
| GET | `/blocks`, `/block` | список блоков файла и получение блока |
| PUT | `/block` | выгрузка блока |
| POST | `/upload`, `/commit` | загрузка файла целиком и фиксация версии |
| GET | `/download`, `/blocks-all` | скачивание файла и всех его блоков |
| DELETE | `/delete` | удаление файла (надгробие) |
| GET | `/events` | подписка на изменения пользователя (SSE) |

Авторизация — заголовок `Authorization: Bearer <токен>`.

## Где что лежит

| Что | Где |
|---|---|
| Настройки клиента и сервера | `client.json` / `server.json` рядом с исполняемым файлом |
| Журналы | `client.log` / `server.log` там же |
| Реестр пользователей и токенов | `users.json` рядом с сервером |
| Файлы пользователей | каталог хранения сервера: `<каталог>\<пользователь>\`, манифест `.manifest.json`, блоки `.blocks\` |
| Снимки экрана клиента | подпапка «Снимки экрана» в папке синхронизации (или «Изображения\POSCloud», если отправка выключена) |

`client.json`, `server.json` и `users.json` содержат токены и в репозиторий не попадают —
они перечислены в `.gitignore`.

## Безопасность

- токены устройств хранятся только хэшами (SHA-256), неавторизованные запросы отклоняются (кроме `/health`);
- имена файлов проверяются на выход за пределы папки пользователя (защита от `..`), служебные каталоги
  (`.blocks`, `.manifest.json`) не синхронизируются;
- сервер не завершает процессы, кроме того, который действительно слушает выбранный порт и только
  после подтверждения пользователя;
- снимки экрана и синхронизируемые файлы уходят на сервер: при включённой отправке снимков это стоит
  помнить, галочка «Отправлять снимки на сервер» отключает их передачу.
